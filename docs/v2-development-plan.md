# v2 开发计划

设计依据：[多事件分块原型](../prototype/boards.html)；v1 基线：[v1 开发计划](v1-development-plan.md)

## 1. 版本目标

v2 在不改变本地数据模型和核心任务规则的前提下，重做 macOS 桌面端的信息架构与视觉层级：

- 用窄应用导航栏替换“事件树 / 时间分组”宽侧栏。
- 事件首页同时展示多个顶层事件卡片，每张卡片直接呈现多级任务结构。
- 卡片根据窗口宽度自动换行，按内容自然增高，不强制占满整列高度。
- 保留任务详情页，以及标题、截止时间、备注、完成、重命名和删除能力。
- 时间线改为连续日期导航，使用“连续 6 天 + 更晚”、上一周、下一周和回到今天。
- 统一为暖灰纸张与深青绿的浅色设计，不再提供 Dark 模式。
- 保留现有 SQLite 数据，升级后用户数据无须迁移。

## 2. 范围与假设

### 包含

- macOS 桌面端，最低支持宽度继续保持 720 px。
- 事件总览、事件详情、时间线、对话框和空状态的 v2 样式。
- 事件卡片内的展开折叠、完成、快速新增、打开详情。
- 事件卡片菜单中的重命名和删除。
- 日期切换、每日数量、逾期区域、显示已完成开关。
- 鼠标 hover、点击光标、键盘焦点、Tooltip 和语义标签。

### 不包含

- 手机和平板布局。
- 登录、同步、提醒、搜索、标签、优先级、附件。
- 数据库表结构调整。
- 时间线拖拽改期。
- 同一张事件卡片内的树节点拖拽重排改版；继续沿用现有规则和可用入口。

### 交互假设

- 顶层节点是一张事件卡片；没有子节点的顶层 todo 也以单项卡片显示。
- 点击节点标题进入现有详情视图；完成圆点只切换完成状态，不打开详情。
- 快速新增按回车只在当前事件卡片中添加，不跳转详情。
- “更晚”包含当前日期条最后一天之后的任务和未设置截止时间的任务。
- 选择今天时，逾期未完成任务显示在当天列表顶部；选择其他日期时不重复显示逾期任务。
- 上一周和下一周以 7 天为步长移动日期窗口；“回到今天”恢复今天为选中项。

## 3. 技术策略

### 保留

- `TodoNode`、`NodeTree`、`NodeService`、`NodeRepository` 和 SQLite 实现。
- `ChangeNotifier` 单控制器方案，不新增状态管理依赖。
- 现有详情编辑、备注、截止时间、删除确认及完成规则。

### 调整

- `DesktopAppShell`：由宽侧栏双栏结构改为 54 px 窄导航栏加工作区。
- `AppController`：用选中日期和日期窗口替代 `TimelineGroup` 会话状态。
- `TimelineQuery`：增加按自然日查询、每日计数和“更晚”查询。
- `EventView`：拆成事件总览与详情两种工作区状态。
- `AppTheme`：只保留 v2 浅色主题，并补齐完成色、逾期背景和事件辅助色 token。

### 建议组件边界

```text
lib/ui/
  adaptive/
    desktop_app_shell.dart
  navigation/
    app_rail.dart
  events/
    event_board_view.dart
    event_card.dart
    event_tree_row.dart
    event_detail_view.dart
  timeline/
    timeline_view.dart
    week_date_strip.dart
    timeline_task_row.dart
  common/
    completion_control.dart
    ...现有对话框
```

只在组件确实被复用或文件职责过大时拆分，不为未来移动端预建抽象。

## 4. 里程碑与提交边界

预计一名开发者全职投入 **8–11 个开发日**。每个模块完成后运行对应检查并单独提交；验收失败时不进入下一模块。

| 模块 | 预计 | 可验收结果 | 建议提交 |
| --- | ---: | --- | --- |
| V2-0 设计基线 | 0.5 天 | 原型、规则和测试基线固定 | `docs: define v2 desktop design target` |
| V2-1 主题与应用壳 | 1 天 | 浅色 token、窄导航栏、事件/时间线切换 | `feat: add v2 desktop shell and light theme` |
| V2-2 事件卡片布局 | 1.5–2 天 | 多事件并排、自动换行、自然高度 | `feat: add responsive event board` |
| V2-3 卡片内任务交互 | 1.5–2 天 | 多级树、完成、展开、快速新增、菜单 | `feat: support task interactions in event cards` |
| V2-4 详情页衔接 | 1 天 | 从卡片进入详情并无损返回，备注等能力保留 | `feat: connect event board to task details` |
| V2-5 时间线领域规则 | 1–1.5 天 | 按日查询、计数、日期窗口和更晚规则 | `refactor: query timeline by selected date` |
| V2-6 时间线界面 | 1.5–2 天 | 连续日期条、周切换、回到今天、任务区 | `feat: add continuous timeline date navigation` |
| V2-7 视觉收口与发布检查 | 1 天 | 对话框、空状态、焦点、文档和 Release 构建 | `chore: finalize v2 desktop experience` |

### V2-0：设计基线

任务：

- 将 `prototype/boards.html`、`boards.css`、`boards.js` 作为 v2 视觉验收基线。
- 固定设计 token、关键尺寸和交互假设。
- 记录当前 `flutter analyze`、`flutter test` 和 macOS build 状态。

验收：

- 原型可以在事件和时间线之间切换。
- 计划中的每个界面区域都能映射到 Flutter 模块。
- v1 自动化测试全通过。

### V2-1：主题与应用壳

任务：

- 将 `AppTheme` 改为纯浅色设计：画布 `#F7F6F2`、导航栏 `#EFEEE9`、强调色 `#26777A`。
- 增加完成色 `#4F7D68`、逾期色 `#C45D4E` 和逾期浅背景 `#F8E9E4`。
- 移除主题切换按钮、`themeMode` 和 Dark 主题代码。
- 将宽侧栏替换为 54 px 应用导航栏，只保留事件、时间线和新建事件。
- 不向 macOS 原生标题栏添加自定义内容。

验收：

- 事件和时间线切换无状态跳变，hover 不改变选中状态。
- 所有导航按钮使用手型指针、Tooltip、键盘焦点和语义标签。
- 窗口宽度 720、1100、1440 px 无溢出。

### V2-2：事件卡片布局

任务：

- 新增事件总览工作区，读取全部顶层节点。
- 每个顶层节点渲染为独立事件卡片，显示标题、说明、完成进度、截止摘要和事件辅助色。
- 使用 `Wrap` 或等价响应式布局，卡片宽度保持在合理区间并自动向下换行。
- 卡片按内容自然增高，不统一拉伸到视口底部。
- 增加“新建事件”占位卡和无事件空状态。

验收：

- 1、3、8 张事件卡片在三种测试窗口宽度下排列正确。
- 长标题、长路径和多级任务不产生横向溢出。
- 滚动只发生在主工作区，不产生嵌套横向滚动。

### V2-3：卡片内任务交互

任务：

- 抽取完整的树行组件，整行负责背景、hover、选中和垂直居中。
- 在卡片内递归展示任意深度节点，并保留展开/折叠。
- 完成状态保持原地并显示删除线，不移动到隐藏的“已完成”区域。
- 快速新增按回车只创建子任务，不触发详情跳转。
- 事件卡片菜单只提供重命名和删除，并沿用统一对话框样式。
- 保证任务行点击、完成圆点、展开箭头和菜单事件互不串扰。

验收：

- 为“快速新增不跳转”“整行 hover 填满”“文字垂直居中”“完成保持原地”增加 Widget 测试。
- 深度至少 4 层的示例树显示与操作正确。
- 重命名和删除路径继续通过现有测试。

### V2-4：详情页衔接

任务：

- 点击任务标题进入聚焦详情，保留现有标题、截止时间、备注和完成操作。
- 增加明确返回事件总览的入口，返回后保留卡片滚动位置和展开状态。
- 详情中的完成状态与卡片实时同步。
- 顶层事件、分支事件和叶子任务都可以打开详情。

验收：

- 总览 → 详情 → 修改 → 返回后数据与 UI 同步。
- 备注持久化、详情完成、删除与撤销的现有测试继续通过。

### V2-5：时间线领域规则

任务：

- 用 `selectedTimelineDate` 和日期窗口起点替代 `TimelineGroup`。
- 实现单日未完成/已完成查询和日期条每日任务计数。
- 实现今天的逾期分区。
- 实现“更晚”查询：日期窗口之后的任务按截止时间排序，无日期任务排在最后。
- 保留事件摘要行和叶子任务行的原有区别。
- 日期变化或时区变化时刷新窗口，但不覆盖用户主动浏览的历史/未来周。

验收：

- 单元测试覆盖跨月、跨年、周切换、夏令时/时区变化、逾期、无日期和显示已完成。
- 相同截止时间继续按 `createdAt`、`id` 稳定排序。
- 此模块只改领域和控制器，不混入界面重构。

### V2-6：时间线界面

任务：

- 在任务列表上方实现月份/周数、上一周、下一周和回到今天。
- 实现 6 个连续日期加“更晚”的日期条。
- 日期项显示相对名称、日号和任务数；选中态使用轻背景与底部短线，不使用独立卡片边框。
- 点击日期同步更新任务列表和日期标题。
- 保留显示已完成开关、今日完成摘要、逾期区和任务路径。
- 加入左右方向键切换日期，以及可见的键盘焦点。

验收：

- 日期切换、回到今天、跨周和“更晚”均有 Widget 测试。
- hover 只提供轻反馈，不改变选中状态。
- 720、1100、1440 px 下日期条和任务列表无溢出。

### V2-7：视觉收口与发布检查

任务：

- 对齐对话框、空状态、Snackbar、阴影、圆角、间距与字号。
- 检查浅色模式文字对比度、鼠标命中范围和键盘 Tab 顺序。
- 删除 v2 替代后不再使用的旧侧栏、旧时间分组和 Dark 主题代码。
- 更新 README 的 v2 界面说明、运行、测试和 build 命令。
- 执行 Release build 并进行真实 macOS 启动检查。

验收：

- `dart format --output=none --set-exit-if-changed lib test`
- `flutter analyze`
- `flutter test`
- `flutter build macos --release`
- 手动检查 Command+Q 退出、关闭窗口不退出、窗口恢复、对话框和滚动行为。

## 5. 测试策略

### 领域测试

- 按日期筛选、逾期、“更晚”、无日期、已完成与稳定排序。
- `now` 跨天及系统时区变化。
- v1 树、完成、移动和删除规则不得回归。

### Widget 测试

- 应用导航栏切换和鼠标状态。
- 事件卡片响应式换行、自然高度和多级树。
- 快速新增、完成、展开、详情返回、右键/更多菜单。
- 日期条选择、周切换、回到今天和完成开关。

### 手动视觉检查

- 使用固定示例数据在 720×700、1100×760、1440×900 三种尺寸截图。
- 对照 HTML 原型检查卡片宽度、行高、垂直居中、hover 填充、颜色和空白。
- 检查长中文、英文混排、4 层以上树结构和大量事件滚动。

## 6. 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 多张卡片同时渲染深树导致卡顿 | 先测真实规模；只有出现证据时才引入懒加载或虚拟化 |
| 卡片中操作与打开详情事件冲突 | 为完成、展开、菜单和标题分别定义命中区并写 Widget 测试 |
| 时间线状态重构影响日期边界 | 领域测试先行，控制器与 UI 分两个提交 |
| 删除旧侧栏导致现有编辑入口丢失 | 在事件卡片和详情均确认对应入口后再删除旧实现 |
| 大范围 UI 重构难以回退 | 严格按模块小提交，不把领域、壳和视觉收口混在同一提交 |

## 7. 完成定义

v2 只有同时满足以下条件才算完成：

- 事件总览和时间线与确认的 HTML 原型在结构和交互上对齐。
- 所有 v1 数据和核心操作可继续使用，无数据库迁移和数据丢失。
- 新增与既有自动化测试全部通过。
- macOS Release 构建成功并完成真实启动检查。
- 每个模块均有独立 Git 提交，工作区不残留意外改动。

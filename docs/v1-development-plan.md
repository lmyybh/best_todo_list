# v1 开发计划

依据：[docs/target.md](target.md)；UI 参考：[prototype/index.html](../prototype/index.html)

## 当前基线

- Flutter macOS v1 已完成，应用名称为“todo”。
- 数据层使用 `sqflite_common_ffi`，应用状态使用 Flutter `ChangeNotifier`。
- HTML 原型已经确认整体方向，覆盖事件树、事件详情、时间线、完成状态和深浅色主题。
- 原型中的示例数据和交互只用于视觉验收；实际业务规则以 `target.md` 为准。
- M0-M5 已于 2026-08-11 完成；`flutter analyze`、20 个自动化测试、macOS Release 构建与真实启动均通过。

## 目标

交付一个桌面端、本地单机的 todo 事件树应用。默认进入事件视图，支持本地创建、编辑、删除、任意深度树、事件视图、时间线视图、完成状态汇总和本地关系型持久化。

## 基本假设

- 技术栈沿用当前 Flutter 工程。
- v1 优先支持桌面端交互与布局；移动端适配不作为验收目标。
- 本地存储采用 SQLite 关系型数据库，应用层只维护 `Node` 一种核心实体。
- 事件完成状态实时推导，不保存为独立字段。
- Root 是隐式概念，不在数据库中创建真实节点；顶层节点的 `parent_id` 为 `NULL`。
- 节点 `id` 在客户端本地生成，v1 不依赖服务端分配 id。
- 不进入 v1 的能力：同步、登录、提醒、搜索、快捷键体系、导入导出、标签、优先级、备注、重复任务、附件。

## 交付策略

采用“领域规则优先、纵向切片交付”的顺序：先让数据规则在测试中成立，再接入事件视图；事件视图完整可用后，时间线只消费同一份领域数据，不再复制业务逻辑。

按一名开发者全职投入估算，v1 预计需要 **12-16 个开发日**。这是工作量估算，不是发布日期承诺：

| 里程碑 | 建议工期 | 可演示产物 |
| --- | ---: | --- |
| M0 项目基线 | 1 天 | 可运行的 macOS 应用壳和自动化检查 |
| M1 领域与持久化 | 3-4 天 | 数据库和领域测试中的完整事件树 |
| M2 事件视图基础 | 3 天 | 从空数据创建、编辑、完成多层事件树 |
| M3 事件视图完整 | 2-3 天 | 删除撤销、排序和跨父移动 |
| M4 时间线 | 2-3 天 | 今天、明天、本周、其他四类执行视图 |
| M5 收尾发布 | 1-2 天 | 可供日常试用的 macOS v1 构建 |

每个里程碑独立验收。前一个里程碑的测试和手动验收没有通过，不进入后一个里程碑。

## 关键决策

### 数据层

- 新增 `nodes` 表：
  - `id TEXT PRIMARY KEY`
  - `parent_id TEXT NULL`
  - `title TEXT NOT NULL`
  - `deadline INTEGER NULL`
  - `created_at INTEGER NOT NULL`
  - `updated_at INTEGER NOT NULL`
  - `completed_at INTEGER NULL`
  - `deleted_at INTEGER NULL`
  - `manual_order INTEGER NOT NULL`
- 时间戳统一保存 UTC 毫秒时间戳，展示时转换为设备本地时间。
- 所有创建、编辑、移动、完成、删除操作都更新 `updated_at`。
- 建立索引：
  - `parent_id, deleted_at, manual_order`
  - `deadline, deleted_at`
  - `completed_at, deleted_at`
  - `created_at, deleted_at`
- `manual_order` 使用同级局部排序值。新建节点默认追加到当前父节点未完成列表末尾；必要时只重排同一父节点下的节点。

### 应用层

- `NodeRepository` 负责数据库读写。
- `NodeService` 负责树规则、完成规则、删除规则、移动规则。
- UI 不直接修改数据库，所有写操作走服务层。
- 应用启动后加载未删除节点构建内存树，用于事件视图、完成状态推导和路径展示；写入后刷新内存状态。
- 日期分组逻辑集中在领域层，并通过可注入的时钟获得“当前时间”，避免测试依赖真实日期。
- 一次用户操作涉及多个节点时必须在单个数据库事务中完成，例如删除子树、跨父移动和批量重排。
- UI 状态与持久化状态分开：展开节点、当前选中项、当前视图和“显示已完成”属于会话状态，不写入 `nodes` 表。

### UI 层

- 先使用 Flutter Material 组件完成桌面端可用体验，避免引入设计系统。
- 主界面使用双栏布局：
  - 左侧导航：事件树或时间分组。
  - 右侧内容：详情、子节点列表或时间线列表。
- 基础编辑采用内联输入；`deadline` 使用日期时间选择器弹层。
- 使用一个应用级控制器协调当前节点集合、选中状态和异步写操作。v1 优先使用 Flutter 自带的可监听状态能力；只有当实现明显复杂化时才引入额外状态管理依赖。
- 主题颜色、间距、圆角和文本样式统一定义在 `ThemeData` 与少量主题扩展中，不把原型色值散落到 Widget 内。
- 所有可点击控件需要 hover、pressed 和键盘 focus 状态；图标按钮提供 tooltip 与语义标签。

### M1：节点模型、本地持久化和领域规则

状态：**已完成（2026-08-11）**

目标：先把 v1 的业务规则做成可测试核心。

任务：

- 实现 `Node` 模型和数据库表。

### M3：事件视图完整规则

状态：**已完成（2026-08-11）**

目标：补齐 v1 事件视图中的删除、撤销和移动排序。

任务：

- 实现删除节点：
  - 递归软删除整棵子树
  - 默认视图隐藏软删除节点
  - 删除后提供短暂撤销
- 实现同级排序：
  - 未完成子节点支持拖拽调整 `manualOrder`
  - 新建节点追加到当前父节点未完成列表末尾
- 实现跨父移动：
  - 在事件视图中把节点移动到另一个父节点下
  - 移动只改变 `parentId` 和新父节点下的 `manualOrder`
  - 移动不改变 `deadline`
  - 移动前校验禁止形成环
- 实现完成节点移动限制：
  - 已完成叶子节点移动前必须先取消完成
  - 已完成事件节点默认禁止移动，并提示需先取消其子任务完成状态
- 实现父子 `deadline` 提示：
  - 子节点 `deadline` 晚于父节点时展示轻量提示

验收：

- 删除后短时间内可撤销，过后仍为软删除状态且不显示。
- 同级拖拽后重启应用排序不丢失。
- 跨父移动后树结构正确，不能把节点移动到自己的子孙节点下。

### M4：时间线视图

状态：**已完成（2026-08-11）**

目标：完成按时间组织的执行视图。

任务：

- 主导航增加事件视图和时间线视图切换。
- 左侧时间分组：
  - 今天
  - 明天
  - 本周
  - 其他
- 默认选中“今天”。
- 实现分组规则：
  - 今天：今天 deadline 的未完成节点，顶部显示逾期未完成节点
  - 明天：明天 deadline 的未完成节点
  - 本周：本周周一到周日 deadline 的未完成节点，包含今天和明天
  - 其他：逾期、本周以外未来、无 deadline
  - 分组是筛选入口，不是互斥集合；当前屏幕一次只显示一个分组
- “其他”内部分为三个区域：
  - 逾期：最接近今天的在前
  - 未来：deadline 最近的在前
  - 无 deadline：按 `createdAt` 排
- 实现时间线展示范围：
  - 叶子节点显示为可执行任务，可勾选完成
  - 有子节点且有 `deadline` 的事件节点显示摘要行和进度，不提供勾选
  - 有子节点且无 `deadline` 的事件节点不显示
  - 每行显示所属路径
- 实现排序：
  - 有 `deadline` 的节点按 `deadline` 升序
  - `deadline` 相同时按 `createdAt` 升序
  - `createdAt` 相同时按 `id` 升序
  - “其他”的无 deadline 区域按 `createdAt`
- 实现“显示已完成”开关：
  - 默认隐藏已完成节点
  - 打开后按 `completedAt` 倒序显示，并保留原 `deadline` 信息
- 时间线不支持拖拽排序；时间归属只能通过编辑 `deadline` 改变。

验收：

- 今天、明天、本周、其他分组结果符合目标文档。
- 逾期未完成节点在“今天”顶部可见。
- 时间线完成叶子节点后，事件视图同步更新状态。

## 测试计划

### 单元测试

- 标题校验：空白标题不能保存。
- 叶子完成：完成写入 `completedAt`，取消完成清空。
- 事件完成：所有子孙叶子完成后事件视为完成，完成时间取最晚 `completedAt`。
- 已完成叶子添加子节点：清空原 `completedAt`。
- 删除子树：节点及所有子孙写入 `deletedAt`。
- 移动防环：禁止移动到自身或子孙节点下。
- 排序：未完成按 `manualOrder`，已完成按 `completedAt` 倒序。
- 时间分组：今天、明天、本周、其他边界。
- 本周边界：周一到周日。

### 数据层测试

- 创建后重新打开数据库仍可查询。
- 软删除节点默认查询不可见。
- 索引相关查询返回稳定排序。
- UTC 存储、本地展示转换不改变原始值。

### Widget 测试

- 事件视图空状态和新增节点。
- 右侧面板内联编辑标题。
- 完成叶子节点后进入已完成组。
- 时间线分组切换。
- 显示已完成开关。

### 手动验收

- 从空应用创建三层事件树。
- 给不同层级节点设置和清空 `deadline`。
- 完成所有叶子，确认父事件自动完成。
- 给已完成事件新增未完成子节点，确认父事件重新未完成。
- 删除一棵子树并撤销。
- 拖拽调整同级排序，重启后排序保留。
- 跨父移动节点，确认路径和时间线展示同步变化。
- 验证逾期、今天、明天、本周、其他分组。

## 主要风险与处理

- 拖拽移动交互复杂：先实现稳定的数据规则和同级排序，再实现跨父移动 UI。
- 时间分组容易出现边界错误：领域层集中处理日期边界，并用固定时钟测试。
- 深层树完成状态推导可能重复计算：v1 先基于内存树递归推导，出现明显性能问题再局部缓存。
- 已完成事件节点无法直接“取消完成”：v1 先禁止移动已完成事件，并提示用户取消某个子任务完成状态。

## v1 完成定义

- 桌面端默认进入事件视图。
- 支持本地创建、编辑、删除、撤销删除、任意深度树。
- 支持事件视图和时间线视图。
- 支持 `createdAt`、可选 `deadline`、叶子 `completedAt`。
- 支持叶子完成和事件完成状态汇总。
- 支持本地 SQLite 持久化，重启后数据保留。
- 所有 v1 非目标能力没有出现在主流程中。

# 目标设计

## v1 范围

v1 先做桌面端、本地单机版本，默认进入事件视图。

包含：

- 本地创建、编辑、删除 todo 节点
- 任意深度的事件树
- 事件视图和时间线视图
- `createdAt`、可选 `deadline`、叶子节点 `completedAt`
- 叶子节点完成、事件节点完成状态汇总
- 本地持久化

暂不包含：

- 多端同步
- 登录账户
- 提醒/通知
- 搜索
- 快捷键体系
- 导入、导出、备份
- 标签、优先级、备注、重复任务、附件

## 核心模型

只维护一种核心实体：节点。

有子节点的节点在概念上就是事件；没有子节点的节点就是普通 todo。不要单独维护 `Event` 和 `TodoItem` 两套模型。

节点字段：

- `id`：客户端本地生成的稳定 id
- `parentId`：父节点 id；顶层节点为 `null`
- `title`：标题，trim 后不能为空，允许重复
- `deadline`：可选，保存为 UTC 时间戳；展示时使用设备本地时间
- `createdAt`
- `updatedAt`
- `completedAt`：只作为叶子节点的真实完成时间
- `deletedAt`：软删除时间
- `manualOrder`：同一父节点下的局部排序值

Root 是隐式概念，不在数据库里创建真实 Root 节点。

## 树结构规则

- 节点形成严格树结构，不允许多个父节点。
- 支持任意深度嵌套。
- 禁止把节点移动到自己的子孙节点下，避免形成环。
- 事件视图里可以调整同级顺序，也可以把节点移动到另一个父节点下。
- 移动节点只改变 `parentId` 和新父节点下的 `manualOrder`，不改变 `deadline`。
- 普通 todo 添加子节点后，自动成为事件。
- 事件的最后一个子节点被删除或移走后，自动变回普通 todo，默认未完成。

## 完成规则

叶子节点可以手动完成和取消完成。

- 完成叶子节点时，记录 `completedAt`。
- 取消完成时，清空 `completedAt`。
- v1 不保留多次完成历史。

事件节点不手动完成，完成状态从子孙叶子节点实时推导：

- 所有子孙叶子都完成时，事件视为完成。
- 事件完成时间由子孙叶子节点推导，取最晚的 `completedAt`。
- 事件完成时间不作为独立事实保存。
- 如果给已完成事件新增未完成子节点，事件重新变为未完成。

如果一个已完成叶子节点后来添加第一个子节点：

- 它变成事件。
- 清空原来的 `completedAt`。
- 新完成状态改由子节点汇总。

已完成节点可以编辑标题和 `deadline`，但移动位置前需要先取消完成。

## 删除规则

删除节点时，软删除整棵子树：

- 递归给节点及所有子孙节点设置 `deletedAt`。
- 默认视图不显示软删除节点。
- 删除后提供短暂撤销。
- v1 不做回收站页面。

## 事件视图

事件视图是 v1 默认首页。

桌面端采用左右两栏：

- 左侧：事件树导航，可展开/折叠。
- 右侧：当前选中节点的详情和子节点列表。

右侧内容：

- 当前节点标题和 `deadline`
- 未完成子节点列表
- 可折叠的已完成组
- 新增子节点入口

排序规则：

- 未完成子节点按 `manualOrder` 排。
- 新建节点默认追加到当前父节点未完成列表末尾。
- `deadline` 只作为信息展示，不影响事件视图排序。
- 已完成节点单独收纳到“已完成”组，可折叠隐藏。
- 已完成组内按 `completedAt` 倒序。
- 当事件整体完成后，它在父节点视图中自动进入“已完成”组。

基础编辑直接在右侧面板内完成，不使用完整编辑弹窗：

- 新增子节点使用内联输入。
- 编辑标题直接在面板中进行。
- 编辑 `deadline` 使用日期时间选择器弹层。

## 时间线视图

时间线视图也是左右结构：

- 左侧：时间分组导航。
- 右侧：当前分组下的任务列表。

左侧分组：

- 今天
- 明天
- 本周
- 其他

默认选中“今天”。

这些分组不是互斥集合，而是筛选入口；同一节点可能符合多个筛选，但当前屏幕一次只显示一个分组，避免同屏重复。

分组规则：

- `今天`：deadline 是今天的未完成节点，并在顶部显示所有逾期未完成节点。
- `明天`：deadline 是明天的未完成节点。
- `本周`：deadline 在本周周一到周日之间的未完成节点，包含今天和明天。
- `其他`：逾期节点、本周以外的未来节点、无 deadline 节点。

`其他` 内部拆成三个区域：

- 逾期：最接近今天的在前。
- 未来：deadline 最近的在前。
- 无 deadline：按 `createdAt` 排。

时间线显示范围：

- 叶子节点显示为可执行任务，可勾选完成。
- 有子节点且有 `deadline` 的事件节点显示为事件摘要行，展示进度，不提供勾选。
- 有子节点且没有 `deadline` 的事件节点不显示在时间线主列表。
- 每行显示所属路径，提供事件上下文。

时间线不支持拖拽排序。

排序规则：

- 有 `deadline` 的节点按 `deadline` 升序。
- `deadline` 相同，按 `createdAt` 升序。
- `createdAt` 也相同，按 `id` 升序保证稳定。
- 无 `deadline` 节点在“其他”的无 deadline 区域按 `createdAt` 排。

时间线默认隐藏已完成节点。打开“显示已完成”后：

- 已完成节点按 `completedAt` 倒序显示。
- 每条仍保留原 `deadline` 信息。

## deadline 规则

- `deadline` 可以为空。
- 一旦设置，必须包含日期和时间，精确到分钟。
- 不做“全天任务”概念。
- UI 可以提供默认时间，但保存值仍然是分钟级。
- 子节点 deadline 可以晚于父节点 deadline，但需要显示轻量提示。
- 修改时间归属只能通过编辑 `deadline`，不能通过拖拽时间线完成。

本周按周一到周日定义。

## 本地持久化

v1 使用本地关系型存储作为数据基础，而不是把整棵树存成一个 JSON 文件。

核心是一张 `nodes` 表，围绕 `parentId`、`deadline`、`createdAt`、`completedAt`、`deletedAt` 建立查询能力。

## 后续同步方向

多端同步不进入 v1，但模型保持 local-first 方向：

- 所有操作先写本地。
- 未来登录后按用户账户同步。
- 冲突合并方向是字段级 last-write-wins。
- 删除使用 `deletedAt` 墓碑。
- 客户端生成稳定 id，避免未来离线创建依赖服务器分配 id。

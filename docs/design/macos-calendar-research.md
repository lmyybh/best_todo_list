# 日程日／周／月视图调研

日期：2026-10-21。范围：现有代码调查、macOS 日历交互参考与实现建议；不修改业务代码。

## 结论

建议把日程改为占满内容区域的日历工作区，提供日／周／月分段切换、日期范围标题、前后导航和“今天”。默认周视图，以便同时看见整周安排；月视图看分布，日视图看细节。

关键前提：当前产品的“事件”是带子节点的任务树节点，不是具有起止时间的日历预约。当前只有截止期限。第一版可以完整呈现三个范围内的截止安排；真正按持续时间绘制的预约块，需要另外引入计划起止时间，不能凭截止期限推算。

以下“建议”是针对本项目的设计判断，不表示 Apple 的原样行为。

## 三个视图建议

| 视图 | 主体结构 | 日期期限 | 定时期限 | 密集内容 |
| --- | --- | --- | --- | --- |
| 日 | 日期头＋单列 24 小时时间轴 | 顶部“当日截止”区 | 放到对应时刻的紧凑标记，显示“14:00 截止” | 同时刻条目并列或分组展开，不能互相遮挡 |
| 周 | 周一至周日七列，共享纵向时间轴 | 各列顶部“当日截止”区 | 各列对应时刻标记 | 同时刻条目分组；展开后能访问所有条目 |
| 月 | 七列、按完整周排列的日期格，覆盖月首月尾 | 标题与所属事件颜色标记 | 时间＋标题 | 根据格子高度显示若干条，“还有 N 项”打开当天完整列表 |

共享交互建议：

- 顶栏统一为日期范围、日／周／月分段控件、上一范围／今天／下一范围。
- 切换视图保留锚定日期；“今天”保留当前视图模式。前后按钮分别移动一天、一周、一月。
- 月视图点击日期选中当天，双击日期进入日视图；“还有 N 项”直接展开当天列表。提供键盘等价操作。
- 明确区分今天、当前选中日期、键盘焦点；今日用醒目标记，选中用浅底色，焦点用轮廓。
- 网格只放紧凑条目，祖先路径通过提示或详情补充，避免把树展开塞进日期格。
- 保留暖灰背景、白色内容、细分隔线与深青绿交互色；条目使用所属事件的颜色，同时提供标题与状态文字。
- 内容区优先留给日历，第一版不再增加一套固定左侧栏。窗口较窄时周视图可横向滚动，日期头和时间轴保持对齐。

## 数据呈现规则建议

1. 日／周／月共用同一范围查询，范围统一为起点包含、终点不包含。月视图查询实际显示的完整周，包括相邻月份的补位日期。
2. 具有自身期限的父事件和任务都可显示；仅用于上下文的祖先不能被算作额外安排。沿用节点 ID 去重，不按标题去重。
3. 逾期条目保留在原期限日期；在今天所在范围提供“逾期 N 项”入口查看跨范围积压，不能把旧任务重复搬到每天的格子里。
4. 无日期的未完成叶子任务进入“未定日期”入口。未来有期限的任务继续在真实日期显示。
5. 建议日历保留已完成节点的原期限位置，使用完成标记；实际完成／放弃记录放入当天活动列表。此项会改变当前展示规则，实现前需明确接受该语义。已放弃节点默认不占主日历，保留活动记录。
6. 已归档节点是否展示应显式定义，不能顺带改变归档规则。建议默认隐藏已归档安排，并保留查看历史的入口；这是待确认的产品选择。
7. 定时期限是一个时间点。显示所需的最小高度只是点击区域，不表示占用时长；密集时通过分组展示解决，不伪造结束时间。

## 真正的时间段安排需要什么

如果“事件安排”包括会议、工作时段或跨天行程，应在保留 Deadline 的基础上增加可选的计划区间，而不是把 Deadline 改成结束时间。

- 定时安排：开始与结束时间，校验结束晚于开始。
- 全天安排：日历日期区间，结束日期采用排他边界；与现有日期期限区分。
- 同一节点可以同时有计划区间和截止期限，UI 需要区分安排与截止标记。
- 跨天安排在每日时间轴切片；月视图可画连续条，跨周续接；查询条件为安排开始早于范围结束且安排结束晚于范围开始。
- 重叠安排按相交区间并列排布；不能仅根据开始时间排序后覆盖。
- 涉及 SQLite 迁移、节点写入、详情编辑和边界测试。重复日程、邀请、系统日历同步、提醒不属于本次三视图请求。

## 实现路径与验证

第一阶段：基于现有期限实现三个视图，不改数据库。

1. 为时间线增加模式与范围状态，提供按日期索引的范围投影。验证日／周／月显示同一批对应日期条目、月末翻页和跨年导航。
2. 抽出公共工具栏，以及共享时间轴的日／周视图和月网格。验证所有有日期节点均能访问；密集日期无静默截断。
3. 接回详情、完成操作、逾期入口、未定日期入口和活动记录。验证节点修改后所有视图更新，且不重复计算上下文祖先。
4. 桌面人工验证宽窄窗口、滚动、键盘焦点和鼠标操作。领域测试覆盖闰年二月、四／五／六行月份、周一至周日、00:00／23:59、同一时刻多任务、日期与时区边界。

第二阶段（确需时间段时）：增加计划区间，再实现跨天条、重叠排布与相应编辑表单。拖拽改期和拉伸时长应在区间模型稳定后另行实现。

技术选择建议（补充组件调查后修订）：优先试用现成 Flutter 日历组件，再决定哪些部分需要自绘。当前任务树、截止点与活动记录语义仍由本项目负责；组件承担日期网格、时间轴和事件布局。本轮未运行组件原型或性能基准。

性能注意：现有查询会多次遍历节点、计算树状态。月视图不要对 42 个日期逐个重新构造树并调用全套查询；应在一次范围投影中复用树和节点元数据，分桶后交给视图。这里只是代码层面的风险判断，不是已测得的性能故障。

## 首版实现记录

用户已明确不要求 macOS 外观，沿用本软件主题。首版使用固定版本 kalender 0.33.0，默认周视图，提供日／周／月导航、日期标题进入日视图、截止点和日期期限展示、所属事件颜色以及详情跳转。原树列表通过“任务列表”入口保留。

定时期限映射为零时长事件，最小点击高度不表示时长；日期期限只在 UI 适配层映射到顶部日期栏，不修改领域类型或数据库。已完成事项保留原期限位置；活动记录继续使用原有列表语义。未增加计划区间、拖拽写入或数据库迁移。日历当前包含有期限的已归档节点，沿用时间线查询未过滤归档的行为。
